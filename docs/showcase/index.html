Object storage your apps already know how to use

ObjeX speaks the AWS S3 HTTP API. Point your SDK at a local endpoint for development, wire it into CI for integration tests, or run a three-node cluster with quorum replication — one static binary, no vendor lock-in.

Capabilities

What you get out of the box

S3

S3-compatible API

PUT, GET, HEAD, DELETE, listing, Range requests, batch delete, CopyObject, and multipart uploads. Works with aws-cli and standard SDKs.

V4

AWS Signature V4

Production-style request signing. Presigned GET/PUT URLs for sharing uploads and downloads without handing out long-lived keys.

FS

Content-addressed blobs

SHA-256 paths, atomic tmp-to-rename writes, MD5 ETags. Orphan cleanup and scheduled integrity verification against stored metadata.

N3

Cluster replication

Rendezvous placement, primary forwarding, quorum writes and deletes, durable replication hints, read repair, peer health, and healing.

DX

Docker Compose profiles

Single-node dev stack on port 9000. Three-node cluster profile with sample membership JSON — no Kubernetes required to try distribution.

OB

Observability

Prometheus metrics at /metrics. Liveness and readiness probes. /cluster JSON for membership and peer reachability during demos and ops.

Cluster mode

See placement pick a primary

Every node loads the same membership list. Given a bucket and key, rendezvous hashing picks the same primary everywhere — no coordinator service required.

Quick start

Run it on your machine

Clone the repo, start Docker Compose, and use the same AWS CLI commands you would against S3.

git clone https://github.com/VishalPainjane/ObjeX.git
cd ObjeX
docker compose up -d --build

# API:  http://localhost:9000
# Health: http://localhost:9000/health/ready
# Metrics: http://localhost:9000/metrics

Default dev credentials are in docker-compose.yml. Change them before any real deployment. 

export AWS_ACCESS_KEY_ID=OBXTESTKEY00000001
export AWS_SECRET_ACCESS_KEY=testsecretkeythatislongenoughforhmacsha256test

aws --endpoint-url http://localhost:9000 s3 mb s3://photos
echo "hello from ObjeX" > hello.txt
aws --endpoint-url http://localhost:9000 s3 cp hello.txt s3://photos/
aws --endpoint-url http://localhost:9000 s3 ls s3://photos/
docker compose -f docker-compose.cluster.yml up -d --build

# Nodes
curl http://localhost:9001/cluster
curl http://localhost:9002/cluster
curl http://localhost:9003/cluster

# Upload via node 2, verify on node 1 — placement + forwarding + replication
go test ./...
go run ./cmd/objex

# Set OBJEX_ACCESS_KEY_ID and OBJEX_SECRET_ACCESS_KEY
# Optional: OBJEX_CLUSTER_CONFIG=configs/cluster-3.json

Compatibility

S3 API surface

All object routes require AWS Signature Version 4 unless noted. Full reference in the repository README.

MethodPath / queryAction
GET/List buckets
PUT/{bucket}/{key}Put object
GET/{bucket}/{key}Get object (Range supported)
HEAD/{bucket}/{key}Head object
DELETE/{bucket}/{key}Delete object
POST/{bucket}?deleteBatch delete (XML body)
PUT/{bucket}/{key} + x-amz-copy-sourceCopy object
POST?uploadsInitiate multipart upload
GET/health/readyReadiness (no auth)
GET/metricsPrometheus scrape (no auth)
GET/clusterCluster status (no auth)

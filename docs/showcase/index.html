Your own S3 storage, on your machine

Upload and download files using the same AWS SDK and CLI you already know — but running locally on your laptop, in CI, or across three servers you control.

No AWS account needed for development. One Docker command to start. Optional cluster mode copies your files across multiple machines so one server dying does not lose data.

Quick start

Running in under a minute

Clone, start Docker, upload a file. Same steps on Mac, Linux, or Windows.

git clone https://github.com/VishalPainjane/ObjeX.git
cd ObjeX
docker compose up -d --build
# Open http://localhost:9000
aws --endpoint-url http://localhost:9000 s3 mb s3://my-bucket
aws --endpoint-url http://localhost:9000 s3 cp hello.txt s3://my-bucket/
docker compose -f docker-compose.cluster.yml up -d --build
curl http://localhost:9001/cluster

What is ObjeX

File storage without the cloud bill

For local development

Your web app uploads profile photos or documents. Point the S3 client at localhost instead of AWS — same code, zero cost per test run.

For CI pipelines

GitHub Actions runs integration tests against a real S3 endpoint in a container. No cloud credentials, no flaky shared staging buckets.

For small self-hosted setups

Three cheap VPS machines each hold a copy of your files. If one goes down, the other two still have your data.

For learning systems code

Readable Go source for placement, replication, and repair — with tests that simulate servers going offline.

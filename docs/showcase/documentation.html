ObjeX Technical Documentation

Complete reference for ObjeX, a self-hosted S3-compatible object store written in Go. Metadata lives in SQLite. Payloads are content-addressed files on disk. All examples below use the development credentials shipped with Docker Compose.

Single node
http://localhost:9000
Cluster nodes
9001, 9002, 9003
Access key

Secret key

Region
us-east-1

Introduction

ObjeX exposes an AWS S3-compatible HTTP API. Clients use the same SDKs, signing rules, and HTTP verbs they already use against AWS, pointed at your ObjeX endpoint instead of s3.amazonaws.com.

The implementation splits concerns deliberately. SQLite holds buckets, object metadata, multipart state, credentials, and replication hints. The filesystem stores opaque blobs at paths derived from SHA256("{bucket}/{key}"). Writes land as temporary files and are renamed into place atomically. ETags are MD5 hex digests (multipart uploads use {md5}-{partCount}).

Use cases

  • Local or air-gapped S3 endpoint for development and integration tests
  • CI fixtures without cloud credentials or network dependencies
  • Edge or on-prem object storage at modest scale
  • Learning distributed storage: placement, quorum, hints, and read repair in readable Go
ObjeX targets correctness and clarity at modest scale. It is not a replacement for multi-petabyte erasure-coded fleets. See the architecture docs on GitHub for design deep-dives.

Authentication

All S3 routes require AWS Signature Version 4 (SigV4). The server validates the Authorization header (or presigned query parameters) against credentials stored in SQLite. Default region for signing is us-east-1.

Public routes (no SigV4)

MethodPathPurpose
GET/health, /health/live, /health/readyLiveness and readiness
GET/metricsPrometheus scrape target
GET/clusterCluster membership and peer status

Internal cluster token

When OBJEX_CLUSTER_INTERNAL_TOKEN is set, inter-node replication requests must include X-ObjeX-Internal-Token. This separates client-facing S3 traffic from internal replicate operations and prevents replication loops.

Change default development credentials before any real deployment. SigV4 protects the API, but default keys are public in the repository.

API: Buckets

Bucket operations map to standard S3 HTTP routes at the service root or bucket path.

MethodPathAction
GET/List buckets
PUT/{bucket}Create bucket
DELETE/{bucket}Delete bucket
HEAD/{bucket}Head bucket
GET/{bucket}?list-type=2List objects (v2)
GET/

List all buckets for the authenticated account. Response is S3 ListAllMyBuckets XML.

aws --endpoint-url http://localhost:9000 s3 ls
PUT/{bucket}

Create an empty bucket. Returns 200 on success.

aws --endpoint-url http://localhost:9000 s3 mb s3://photos
curl -X PUT http://localhost:9000/photos \
  -H "Authorization: AWS4-HMAC-SHA256 ..." \
  -H "x-amz-date: ..."
DELETE/{bucket}

Delete an empty bucket. Bucket must contain no objects.

aws --endpoint-url http://localhost:9000 s3 rb s3://photos
HEAD/{bucket}

Check bucket existence. Returns 200 if the bucket exists, 404 otherwise.

aws --endpoint-url http://localhost:9000 s3api head-bucket --bucket photos
GET/{bucket}?list-type=2

List objects in a bucket (ListObjectsV2). Supports prefix, max-keys, and continuation-token.

aws --endpoint-url http://localhost:9000 s3 ls s3://photos/
aws --endpoint-url http://localhost:9000 s3api list-objects-v2 --bucket photos --prefix images/

API: Objects

MethodPathAction
PUT/{bucket}/{key}Put object
GET/{bucket}/{key}Get object (supports Range)
HEAD/{bucket}/{key}Head object
DELETE/{bucket}/{key}Delete object
PUT/{bucket}/{key}

Upload object bytes. Body is the raw file content. Response includes ETag header.

echo "hello world" > hello.txt
aws --endpoint-url http://localhost:9000 s3 cp hello.txt s3://photos/hello.txt
GET/{bucket}/{key}

Download object bytes. Supports Range header for partial reads.

aws --endpoint-url http://localhost:9000 s3 cp s3://photos/hello.txt out.txt
aws --endpoint-url http://localhost:9000 s3api get-object \
  --bucket photos --key hello.txt out.bin
HEAD/{bucket}/{key}

Return object metadata without body. Includes Content-Length and ETag.

aws --endpoint-url http://localhost:9000 s3api head-object \
  --bucket photos --key hello.txt
DELETE/{bucket}/{key}

Delete a single object. In cluster mode, deletion is coordinated with quorum and versioned tombstones.

aws --endpoint-url http://localhost:9000 s3 rm s3://photos/hello.txt

API: Multipart uploads

Large files can be uploaded in parts. Query parameters select multipart operations on the same object path.

QueryMethodAction
?uploadsPOSTInitiate multipart upload
?uploadId=…&partNumber=nPUTUpload part
?uploadId=…POSTComplete upload
?uploadId=…DELETEAbort upload
?uploadsGETList in-progress uploads

Full multipart workflow

export AWS_ACCESS_KEY_ID=OBXTESTKEY00000001
export AWS_SECRET_ACCESS_KEY=testsecretkeythatislongenoughforhmacsha256test
export AWS_DEFAULT_REGION=us-east-1
ENDPOINT=http://localhost:9000

# Create bucket and large test file
aws --endpoint-url $ENDPOINT s3 mb s3://uploads
dd if=/dev/urandom of=large.bin bs=1M count=10

# Initiate
UPLOAD_ID=$(aws --endpoint-url $ENDPOINT s3api create-multipart-upload \
  --bucket uploads --key large.bin --query UploadId --output text)

# Upload part 1 (first 5 MB)
dd if=large.bin of=part1.bin bs=1M count=5
ETAG1=$(aws --endpoint-url $ENDPOINT s3api upload-part \
  --bucket uploads --key large.bin --part-number 1 \
  --body part1.bin --upload-id "$UPLOAD_ID" --query ETag --output text)

# Upload part 2 (remaining bytes)
dd if=large.bin of=part2.bin bs=1M skip=5
ETAG2=$(aws --endpoint-url $ENDPOINT s3api upload-part \
  --bucket uploads --key large.bin --part-number 2 \
  --body part2.bin --upload-id "$UPLOAD_ID" --query ETag --output text)

# Complete
aws --endpoint-url $ENDPOINT s3api complete-multipart-upload \
  --bucket uploads --key large.bin --upload-id "$UPLOAD_ID" \
  --multipart-upload "Parts=[{ETag=$ETAG1,PartNumber=1},{ETag=$ETAG2,PartNumber=2}]"

# Verify
aws --endpoint-url $ENDPOINT s3api head-object --bucket uploads --key large.bin

# Abort example (if needed before complete)
# aws --endpoint-url $ENDPOINT s3api abort-multipart-upload \
#   --bucket uploads --key large.bin --upload-id "$UPLOAD_ID"

API: Batch delete

POST/{bucket}?delete

Delete multiple keys in one request. Send XML body with Content-Type: application/xml.

cat > delete.xml <<'EOF'
<Delete>
  <Object><Key>file-a.txt</Key></Object>
  <Object><Key>file-b.txt</Key></Object>
  <Object><Key>images/old.png</Key></Object>
</Delete>
EOF

aws --endpoint-url http://localhost:9000 s3api delete-objects \
  --bucket photos \
  --delete file://delete.xml

Response is S3 DeleteResult XML listing deleted keys and any per-key errors.

API: Copy object

PUT/{bucket}/{key}

Copy an existing object to a new key using the x-amz-copy-source header. Value format: /{source-bucket}/{source-key} (URL-encoded if needed). 

aws --endpoint-url http://localhost:9000 s3 cp s3://photos/hello.txt s3://photos/hello-copy.txt

aws --endpoint-url http://localhost:9000 s3api copy-object \
  --bucket photos \
  --key backup/hello.txt \
  --copy-source photos/hello.txt

API: Utilities

GET/api/presign/{bucket}/{key}

SigV4-protected helper that returns a JSON presigned URL. Query params: expires (seconds), optional method (GET or PUT). 

# Presigned GET (requires SigV4 on this helper endpoint)
curl -s "http://localhost:9000/api/presign/photos/hello.txt?expires=3600" \
  -H "Authorization: ..." | jq -r .url

# Presigned PUT
curl -s "http://localhost:9000/api/presign/photos/new.txt?expires=3600&method=PUT" \
  -H "Authorization: ..." | jq -r .url
GET/health/live

Liveness probe. No authentication. Returns JSON when the process is running.

curl -s http://localhost:9000/health/live
GET/health/ready

Readiness probe. Checks metadata store and blob directory are writable.

curl -s http://localhost:9000/health/ready
GET/metrics

Prometheus text exposition. Request, storage, replication, and cluster-forward counters.

curl -s http://localhost:9000/metrics | head -20
GET/cluster

Cluster membership, placement config, and peer reachability. No authentication.

curl -s http://localhost:9001/cluster | jq .

Code examples: Python (boto3)

#!/usr/bin/env python3
"""ObjeX boto3 example."""
import boto3
from botocore.client import Config

ENDPOINT = "http://localhost:9000"
ACCESS_KEY = "OBXTESTKEY00000001"
SECRET_KEY = "testsecretkeythatislongenoughforhmacsha256test"
BUCKET = "python-demo"

s3 = boto3.client(
    "s3",
    endpoint_url=ENDPOINT,
    aws_access_key_id=ACCESS_KEY,
    aws_secret_access_key=SECRET_KEY,
    region_name="us-east-1",
    config=Config(signature_version="s3v4"),
)

# Create bucket (ignore if exists)
try:
    s3.create_bucket(Bucket=BUCKET)
except s3.exceptions.BucketAlreadyOwnedByYou:
    pass

# Upload
body = b"Hello from boto3 and ObjeX."
s3.put_object(Bucket=BUCKET, Key="greeting.txt", Body=body)

# Download
resp = s3.get_object(Bucket=BUCKET, Key="greeting.txt")
data = resp["Body"].read()
print(data.decode())

# List
for obj in s3.list_objects_v2(Bucket=BUCKET).get("Contents", []):
    print(obj["Key"], obj["Size"])

# Delete
s3.delete_object(Bucket=BUCKET, Key="greeting.txt")
s3.delete_bucket(Bucket=BUCKET)

Code examples: Node.js (@aws-sdk/client-s3)

// npm install @aws-sdk/client-s3
import { S3Client, CreateBucketCommand, PutObjectCommand,
         GetObjectCommand, ListObjectsV2Command, DeleteObjectCommand,
         DeleteBucketCommand } from "@aws-sdk/client-s3";

const ENDPOINT = "http://localhost:9000";
const ACCESS_KEY = "OBXTESTKEY00000001";
const SECRET_KEY = "testsecretkeythatislongenoughforhmacsha256test";
const BUCKET = "node-demo";

const client = new S3Client({
  region: "us-east-1",
  endpoint: ENDPOINT,
  forcePathStyle: true,
  credentials: { accessKeyId: ACCESS_KEY, secretAccessKey: SECRET_KEY },
});

async function main() {
  await client.send(new CreateBucketCommand({ Bucket: BUCKET }));

  await client.send(new PutObjectCommand({
    Bucket: BUCKET,
    Key: "greeting.txt",
    Body: "Hello from Node.js and ObjeX.",
  }));

  const get = await client.send(new GetObjectCommand({
    Bucket: BUCKET,
    Key: "greeting.txt",
  }));
  console.log(await get.Body.transformToString());

  const list = await client.send(new ListObjectsV2Command({ Bucket: BUCKET }));
  console.log(list.Contents?.map((o) => o.Key));

  await client.send(new DeleteObjectCommand({ Bucket: BUCKET, Key: "greeting.txt" }));
  await client.send(new DeleteBucketCommand({ Bucket: BUCKET }));
}

main().catch(console.error);
forcePathStyle: true is required. ObjeX uses path-style URLs (http://localhost:9000/bucket/key), not virtual-hosted style.

Code examples: Go (aws-sdk-go-v2)

package main

import (
	"context"
	"fmt"
	"log"
	"strings"

	"github.com/aws/aws-sdk-go-v2/aws"
	"github.com/aws/aws-sdk-go-v2/config"
	"github.com/aws/aws-sdk-go-v2/credentials"
	"github.com/aws/aws-sdk-go-v2/service/s3"
)

func main() {
	const (
		endpoint = "http://localhost:9000"
		access   = "OBXTESTKEY00000001"
		secret   = "testsecretkeythatislongenoughforhmacsha256test"
		bucket   = "go-demo"
		key      = "greeting.txt"
	)

	cfg, err := config.LoadDefaultConfig(context.TODO(),
		config.WithRegion("us-east-1"),
		config.WithCredentialsProvider(credentials.NewStaticCredentialsProvider(access, secret, "")),
	)
	if err != nil {
		log.Fatal(err)
	}

	client := s3.NewFromConfig(cfg, func(o *s3.Options) {
		o.BaseEndpoint = aws.String(endpoint)
		o.UsePathStyle = true
	})

	ctx := context.TODO()

	_, err = client.CreateBucket(ctx, &s3.CreateBucketInput{Bucket: aws.String(bucket)})
	if err != nil && !strings.Contains(err.Error(), "BucketAlreadyOwnedByYou") {
		log.Fatal(err)
	}

	_, err = client.PutObject(ctx, &s3.PutObjectInput{
		Bucket: aws.String(bucket),
		Key:    aws.String(key),
		Body:   strings.NewReader("Hello from Go and ObjeX."),
	})
	if err != nil {
		log.Fatal(err)
	}

	out, err := client.GetObject(ctx, &s3.GetObjectInput{
		Bucket: aws.String(bucket),
		Key:    aws.String(key),
	})
	if err != nil {
		log.Fatal(err)
	}
	defer out.Body.Close()
	buf := make([]byte, 256)
	n, _ := out.Body.Read(buf)
	fmt.Println(string(buf[:n]))
}

Cluster: Quorum (N, W, R)

Replication uses configurable quorum parameters. On the 3-node Docker profile, defaults are N=3, W=2, R=2.

SymbolEnv variableMeaning3-node default
NOBJEX_REPLICATION_FACTORNodes in the replica set (primary + replicas)3
WOBJEX_WRITE_QUORUMWrite acknowledgements required before success2
ROBJEX_READ_QUORUMReplicas consulted on read2

Rendezvous hashing selects a primary and N - 1 replicas per (bucket, key). Non-primary nodes forward object requests to the primary. The coordinator fans out writes, records hints for lagging peers, and performs read repair on GET when versions diverge.

Operations: Background jobs

The main binary starts maintenance workers automatically from cmd/objex.

  • Orphan blob cleanup: metadata says deleted, but the file still exists on disk
  • Multipart cleanup: abandoned upload sessions past expiry are removed
  • Integrity verification: re-hash stored bytes and compare to recorded ETag
Jobs run in the background without separate CLI flags. Tune intervals via environment if documented in internal/jobs source.

Troubleshooting

Common errors and how to resolve them during local development or cluster testing.

403 Forbidden / SignatureDoesNotMatch

Verify access key, secret key, and region (us-east-1). Ensure the clock is accurate. For presigned URLs, check expiry and that the URL was not modified.

Connection refused on port 9000

Confirm ObjeX is running: docker compose ps or check the go run process. Cluster nodes use 9001, 9002, 9003.

404 NoSuchBucket / NoSuchKey

Create the bucket first with s3 mb. Keys are case-sensitive. Path-style URLs require forcePathStyle in SDK clients.

BucketAlreadyExists

Bucket names are global within the ObjeX instance. Pick a different name or delete the existing bucket if empty.

Cluster read returns stale or missing data

Check /cluster for peer reachability. Writes need W acknowledgements. A lagging replica may catch up via hints or read repair on GET.

Upload fails with size limit
